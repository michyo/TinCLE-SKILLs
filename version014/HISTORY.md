# TinCLE Version History / Changelog

All notable changes to the TinCLE AI-First Game Engine project will be documented in this file.

---

## Version 0.14 - 2026/10/08 [ Chuuko ]

* Universal Touch & Multi-Touch Gesture Pipeline APIs (`tincle_get_touch_count`, `tincle_get_touch`, `tincle_screen_pressed`): Added a robust, cross-platform touch input architecture to core engine runtime (`tincle.dll` & `tincle.a`). Exposes low-latency multi-touch tracking supporting up to 10 simultaneous touch points with precision coordinates and pressure metrics, alongside a unified `tincle_screen_pressed` API that seamlessly bridges single-tap and mouse-click inputs. Guarantees 100% reliable input handling for mobile browsers, Android tablets, and PC environments without double-trigger issues.
* Raw Texture Access & External Module Integration API (`tincle_get_texture`): Introduced direct pointer extraction for internal cached image assets (`img_id`), returning the underlying `SDL_Texture*`. Empowers custom geometry pipelines and external 3D rendering modules (such as `vtrushka`) to perform low-overhead texture mapping directly within the TinCLE rendering loop, vastly expanding engine extensibility while preserving strict memory bounds and boundary checking.
* Raw Pixel Buffer & Procedural Texture Creation API (`tincle_create_image_from_pixels`): Introduced a high-performance in-memory texture generation pipeline supporting 1 to 4 channel raw pixel arrays (Grayscale, Grayscale+Alpha, RGB, RGBA). Enables dynamic texture synthesis and seamless integration with external 3D data formats (such as VRML `PixelTexture`) by safely normalizing byte streams into managed `img_id` handles with automatic memory validation.
* Enhanced Mobile Web & Touch Interaction Protocol in High Level Skill (`SKILL_ADD1.md`): Integrated explicit prompt directives and developer guidelines for mobile/tablet WebAssembly targets. Recommends designing core game mechanics around a maximum of 2 simultaneous touch points to prevent input suppression caused by OS-level multi-finger system gestures (e.g., Android 3-finger screenshot shortcuts). Enforces automatic fallback instructions and user-facing notifications for games requiring 3+ multi-touch interactions, ensuring flawless AI code generation for mobile web distribution.
* Lightweight VRML 2.0 3D World Rendering & Interactive Scene Engine (`vtrushka` / `SKILL_AON2.md`): Integrated the complete Pure C99 3D parser and software rendering module (`vtrushka.dll` & `vtrushka.wasm`). Allows loading and rendering standard VRML 2.0 (`.wrl`) scenes, supporting node transformations, camera controls (`Viewpoint`), materials, `PixelTexture`/`ImageTexture` mapping, and interactive node triggers without external heavy 3D engine overhead. Fully compatible with both Windows desktop builds and Emscripten WebAssembly runtimes.
* Standardized Agentic Skill Architecture & Metadata Front-Matter Framework (`SKILL.md`, `SKILL_ADD*.md`, `SKILL_AON*.md`, `SKILL_PT.md`, `SKILL_FB.md`, `SKILL_PN.md`): Upgraded the entire talent chip specification system to seamlessly align with next-generation AI skill discovery standards (including Google Gemini Skill protocols, Claude Code, OpenAI Codex, and Antigravity Agent frameworks). Enforced strict, unified YAML front-matter metadata across all core and modular skill definitions using explicit `Use when` trigger logic, precision domain tagging, and version contracts (`v0.14`). Vastly optimizes RAG retrieval accuracy, context boundary isolation, and agentic tool invocation reliability across all modern LLM architectures.
* Added Mandatory Note Value & Duration Lookup Table (Section 1): Explicitly defined standard, dotted, and rest note durations (quarter beats, 8th units, 16th ticks) at the very top of the specification. This lookup table strictly enforces accurate pitch/duration parsing for LLMs and prevents prompt memory miscalculations, explicitly clarifying that explicit note suffixes override default `Ln` values.
* Complete ASCII Encoding Refactoring: Purged all non-ASCII unicode and multibyte characters across the entire document. Replaced formatting symbols with strict ASCII-compatible syntax to prevent parser tokenization errors, bit-stream corruptions, and multi-language context decoding bugs in downstream AI agents.

## Version 0.13 - 2026/09/26 [ Pyonta ]

* Integrated Cross-Origin Local Web Server Utility ("churro"): Introduced "churro" (TinCLE COOP/COEP Header Unlocked Rapid Runtime Open-server) to the standalone sweets-series toolchain. Designed for seamless, one-click offline execution testing of WebAssembly (Emscripten) builds generated by "emcass". Automatically injects mandatory HTTP isolation headers (`Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`) to prevent browser security errors and force-HTTPS redirection failures on localhost. Features multi-threaded concurrent binary streaming for large `.data` and `.wasm` packages, dynamic directory listing fallback, automatic default browser spawning, and clean single-keypress terminal shutdown.
* Integrated Platform Compliance & Content Safety Skill (`SKILL_PCG.md`): Added dedicated compliance guidelines defining photosensitivity limits (ITU BT.1702-3), audio safety, IP protection, and rating zoning (General vs. Explicit/Gore modes) to prevent store rejections on Steam, itch.io, and mobile platforms. Updated core `SKILL.md` to strictly enforce `SKILL_PCG.md` review at project setup.
* Enforced Multi-Primitive Visual Synthesis Standard in Core Skill (`SKILL.md`): Introduced a mandatory AI prompt directive requiring procedural and code-based graphics to be constructed by compositing multiple primitive shapes (lines, rects, ellipses, polygons) rather than relying on single shapes. This standard elevates visual fidelity for assetless prototyping, generating richer, instantly recognizable, and highly expressive graphics purely via code execution.
* Integrated Legacy Outputter Like LIne Printer Of Pdf ("lollipop"): Added "lollipop" to the standalone sweets-series toolchain, a virtual line-printer engine designed to bake source code into physical-first, ultra-readable A4 landscape PDF archives. Inspired by classic continuous forms, it features 132x66/66x33 fixed-width grid alignment, 5-digit zero-padded line numbering (`00001 |`), alternating zebra-stripe background tracks for enhanced eye-tracking, and dual-layer rendering that pairs sharp rasterized glyphs with invisible PDF text streams (`3 Tr`) for seamless copy-paste capability. Built to counter bit-rot, cloud service shutdowns, and disk failures, it provides an incorruptible, paper-ready snapshot of your code legacy.
* Enhanced Dual-Mode Smart Console Attachment in Core Engine (`tincle_core.c`): Dynamically resolves console attachment by binding directly to the parent process window (`AttachConsole`) when invoked via CLI terminals or autonomous AI agent runners, eliminating redundant pop-up windows and preserving stdout/stderr logs on exit. Automatically falls back to dedicated allocation (`AllocConsole`) when launched via Explorer double-click. Enforces unbuffered output (`setvbuf`) for real-time log ingestion and simulates clean terminal prompt recovery upon shutdown, significantly reducing token/credit overhead for AI agent workflows while enabling persistent debug log inspection for human developers.
* Added Preserve-Buffer Flag (`-pb`) to Emscripten Assistant (`emcass`): Introduced the `-pb` command-line option to explicitly inject `preserveDrawingBuffer: true` into WebGL context attributes within the target HTML template. Designed to overcome frame-clearing constraints on strict web hosting environments and user-game platforms (such as PLiCy) that rely on DOM-level canvas buffer extraction for automated screen capture, thumbnail generation, and state snapshots. When omitted, `emcass` retains its zero-overhead default pipeline for maximum execution speed and reduced memory consumption on standard web targets.

## Version 0.12 - 2026/09/09 [ Kyukkyu ]

* Integrated "gatochoc" Immediate-Mode GUI Addon Library: Introduced the all-new, lightweight GUI extension "gatochoc" (`gatochoc.dll`, `gatochoc.wasm`, and `gatochocmt.wasm`) alongside the "SKILL_GT.md" talent chip. Seamlessly exposes the full Nuklear immediate-mode GUI framework into TinCLE games across both `TINCLE_MODE_2D_NORMAL` (`SDL_Renderer*`) and `TINCLE_MODE_GLSL_HERO` (`OpenGL`/`GLES2`) pipelines. Features multi-font loading with Japanese preset support (`GATOCHOC_FONT_JAPANESE`) and strict frame-synchronized input handling for zero-latency, bug-free UI controls on Win32 and WebAssembly targets.
* Low-Level SDL2 Event Interceptor Pipeline API: Added the event callback mechanism (`tincle_set_event_callback` and `tincle_event_cb_t`) to pass raw `SDL_Event*` instances directly into custom user event handlers or third-party extension modules. Enables extensions like "gatochoc" to intercept and consume mouse/keyboard inputs before they reach standard game logic, preventing input bleed-through.
* Native Window & Graphics Context Accessor APIs: Exposed low-level system handles through `tincle_get_window()` and `tincle_get_gl_context()`. Grants developers and extension authors direct access to internal `SDL_Window*` and `SDL_GLContext` handles, enabling seamless integration of custom rendering backends, native OS windows manipulation, and advanced hardware-accelerated GUI layers without modifying the core engine binary.
* Decoupled "cannoli" Physics Engine into WebAssembly Dynamic Modules: Refactored the "cannoli" physics addon library for WebAssembly targets by transitioning from a heavy static library (`cannoli.a`) to dynamic WebAssembly side modules (`cannoli.wasm` and `cannolimt.wasm`). This matches the native Win32 DLL architecture (`cannoli.dll`), unifying the extension architecture across both native and Web targets. This change dramatically reduces core game binary footprints, speeds up iterative compilation, and enables dynamic runtime loading of Box2D/Box3D physics features for web-based games.
* Enhanced "pisstrak" Talent Chip with Dynamic MML Duration & Bar Calculation: Upgraded the "SKILL_PT.md" talent chip with a formal, mathematically enforced duration-calculation protocol. By dynamically resolving target bar counts and song structures prior to MML code generation, the AI composer now guarantees exact millisecond-level match with user-requested track lengths while entirely eliminating runaway generation loops and infinite token overflow errors.

## Version 0.11 - 2026/08/30 [ Satin ]

* Integrated "wipee" Distribution Packaging Tool: Introduced "wipee" (TinCLE Whole Integration Packager for Executable Environment) to the toolchain to automate release distribution archives. Features native Raw Deflate compression for maximum compatibility with standard ZIP extractors and WebAssembly hosting platforms (e.g., itch.io), alongside an optional Malformed ZIP mode (`-m`) designed to ensure reliable delivery against aggressive security scanner heuristics.
* Decoupled AI Agent Skill Delivery Mechanism via GitHub Gist: Migrated the core "SKILL_*.md" rulesets to official GitHub Gist mirrors to bypass overly restrictive cloud security filters (e.g., Microsoft Copilot) that falsely flagged C API definitions as hazardous file attachments. Enables seamless skill injection by directly passing Gist URLs into AI chat prompts, enhancing cross-platform AI accessibility and overall developer workflow flexibility.
* Optimized Agentic Build Pipeline Rules ("SKILL_*.md" & "exsass.txt"): Re-architected the asset manifest specification and AI prompt instructions in "SKILL_*.md". Strictly enforced extension-based pattern matching rules for "asspack" and "emcass", completely mitigating asset file declaration errors by LLM agents and ensuring 100% deterministic asset collection during automated build pipelines.
* Non-Blocking Asynchronous GLSL Shader Compilation Architecture: Overhauled the GLSL shader runtime engine to fully support non-blocking asynchronous shader compilation across WebGL/GLES targets. Integrated background polling (`tincle_shader_poll_async`) and runtime status checks (`tincle_shader_is_ready`), seamlessly eliminating frame hitches and preventing web browser freeze states during heavy shader compilation.
* Enhanced Compiler Toolchain Option Passthrough ("tinclec" & "emcass"): Expanded command-line flag handling in "tinclec" and "emcass" to directly forward advanced, custom compiler flags (such as `-sASYNCIFY` for Emscripten) and raw build options directly to "tcc" and "emcc". Grants developers full granular control over high-performance WebAssembly runtime flags and native build parameters directly through the TinCLE build wrappers.
* Standardized SDL2 Core Header Exposure and AI Context Prompting: Explicitly exposed bundled SDL2 input sub-headers (`SDL_gamecontroller.h`, `SDL_keycode.h`, etc.) within the core skill templates and added strict AI-facing directive prompts. Eliminates hallucinated macro definitions and manual scan-code array declarations by LLM agents, guaranteeing 100% type-safe and compliant native input code generation across all platform targets.
